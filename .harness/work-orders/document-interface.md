# 공식 DOCX 원고 입력 계약

## 입력

`docs/draft/proposal.md`는 UTF-8이며 다음 메타데이터 블록과 정확한 8개 2단계 제목을 순서대로 사용한다. 아래는 문법 정의이며 예시 본문·가짜 제출 자료가 아니다.

- 첫 세 줄: `---`, `project_name: 비식별 앱명`, `---`이다. 앱명은 한 줄의 일반 문자열이며 인용부호·개인명·연락처를 넣지 않는다.
- 메타데이터에는 `participant_unit: individual`, `participant_category: student`를 선택적으로 추가할 수 있다. 생략하면 두 체크박스 모두 원본 상태로 둔다. 허용값은 각각 `individual`, `student`뿐이다. 성명·소속·메일·전화·서명·날짜 등 다른 메타데이터는 허용하지 않는다.
- 본문 제목은 아래 문자열과 정확히 일치해야 한다. 제목 전후에 빈 줄을 둔다. 각 항목의 내용은 비어 있으면 안 된다.

1. `## 1. 앱 한 줄 소개`
2. `## 2. 기획 배경`
3. `## 3. 앱 주요 기능 및 차량 특화 요소`
4. `## 4. 주요 사용 시나리오`
5. `## 5. 개발 계획`
6. `## 6. 기대효과 및 발전 가능성`
7. `## 7. 참고자료`
8. `## 8. 숏폼 링크`

## 지원 Markdown

- 문단은 빈 줄로 분리한다. 문단 내부의 줄바꿈은 공백으로 연결한다.
- 항목 내부 소제목은 `###`~`######`을 사용한다. 공식 1~8 제목을 대체하는 `#` 제목은 사용하지 않는다.
- 목록은 `- `, `* ` 또는 `1. ` 형식을 사용한다. 2칸 들여쓰기마다 하위 단계로 처리하며 최대 3단계를 지원한다. 목록 한 항목은 한 줄로 작성한다.
- 표는 파이프 구문과 구분행을 사용한다. 표 머리행과 모든 본문 행의 열 수를 맞춘다. 셀 안 줄바꿈·중첩 표·병합은 지원하지 않는다. 셀 안 파이프는 `\|`로 쓴다. 표와 목록은 앞뒤 빈 줄로 분리한다.
- 표 바로 다음에 `<p>표 n. 설명.</p>` 또는 `<p align="center">표 n. 설명.</p>` 캡션을 한 줄로 둔다. 최종 원고의 Markdown 표는 머리행·본문 행·캡션을 함께 유지하고, 주변 서술은 연속 입력 행으로 쪽을 넘긴다. LibreOffice 중첩 표 머리행의 고립을 막기 위한 배치이며 최종 렌더에서 모든 표가 한 쪽 안에 들어가는지 확인한다. 한 쪽보다 큰 표를 추가하면 재배치와 전 페이지 검수가 필요하다.
- 링크는 `[표시문](https://주소)` 또는 원문 URL을 사용한다. 링크 표시문뿐 아니라 URL도 PDF에서 읽을 수 있게 함께 표시하며 DOCX에 실제 하이퍼링크를 설정한다. 외부 주소를 접속하거나 업로드하지 않는다.
- URL에 리터럴 괄호 `(`·`)` 또는 백슬래시 이스케이프가 있으면 출력 교체 전에 오류로 거부한다. 괄호는 `%28`·`%29`처럼 URL 인코딩해 작성한다. 링크 표시문의 이스케이프·중첩 대괄호도 지원하지 않는다. 미지원 링크를 짧게 잘라 정상 링크로 생성하지 않는다.
- 인라인 굵게 `**문구**`, 기울임 `*문구*`, 코드 표기 `` `문구` ``를 지원한다. 코드 블록·이미지·수식·각주·임의 HTML은 지원하지 않는다. 미지원 구문은 조용히 삭제하지 않고 오류로 보고한다.
- 참고문헌·AI 활용 기록은 필요한 1~8 항목 안의 소제목·문단·목록으로 통합한다. 8개 항목 밖의 부록은 허용하지 않는다.

## 생성·변환 절차

`tools/build_document.py`는 공식 원본의 알려진 SHA-256을 확인하고 10개 최상위 표 중 가운데 8개 입력표에 원고를 넣는다. 01·03·04의 개인 값·동의·서명 공란은 유지한다. 비식별 앱명은 세 곳의 프로젝트명 줄에만 채우고 선택 메타데이터가 있으면 01 참가 단위/부문만 체크한다. 원본 동의 문구는 변경하지 않는다.

02의 자유서술 입력박스는 원본 1행×1열을 페이지 흐름용 연속 1열 행으로 확장한다. 외곽 표 8개와 항목명·순서·하나의 박스로 보이는 외곽선은 유지하고 내부 행 구분선은 두지 않는다. 01 구성원표·03 동의문구·04 서명표의 구조와 본문 문장·수치는 바꾸지 않는 렌더용 변경이다.

최종 실행 지시 뒤 저장소 루트에서 `python3 tools/build_document.py`를 실행한다. 필요 패키지는 `python-docx`이고 PDF 변환에는 로컬 LibreOffice, PNG 렌더에는 Poppler의 `pdfinfo`, `pdftoppm`이 필요하다. 스크립트는 도구 부재 시 실패하며 대체 PDF·가짜 파일을 생성하지 않는다. 글꼴 기본값은 `Apple SD Gothic Neo`이고 설치 글꼴과 실제 글리프는 최종 렌더에서 확인한다. `--font`로 설치된 한국어 글꼴을 지정할 수 있다.

2026-10-23 실제 실행에서는 기본 Python에 패키지가 없어 `tools/.venv`를 생성하고 python-docx 1.2.0을 설치했다. 재실행은 `tools/.venv/bin/python tools/build_document.py --replace`를 사용한다. 로컬 가상환경은 제출물이 아니다.

출력은 `submission/application-review.docx`, `submission/application-review.pdf`, `.private/visual-review/final/page-XX.png`, `.private/visual-review/manifest.json`이다. 기존 출력이 있으면 기본적으로 중단한다. 명시적 `--replace` 실행은 기존 출력과 이전 페이지 이미지를 교체하며 기존 manifest를 먼저 무효화한다. 원본과 원고는 덮어쓰지 않는다. 도구 실행은 shell 없이 인수 배열로 수행하고, 변환용 LibreOffice 임시 프로필을 사용한다.

`--input`은 저장소 내부로 해석되는 실제 파일만 허용한다. 외부 원고와 외부를 가리키는 입력 링크는 기존 산출물을 변경하기 전에 거부한다. 출력 파일 및 저장소 내부 상위 디렉터리의 심볼릭 링크는 내부·외부 대상과 관계없이 거부한다. 원본·원고와 같은 하드링크 또는 원고를 포함하는 삭제 대상 디렉터리도 거부한다. DOCX는 새 임시 파일에 저장한 뒤 출력 디렉터리 항목을 교체하므로 기존 파일 링크를 따라 저장하지 않는다.

manifest에는 공식 원본·원고·출력 DOCX·PDF의 해시, 실제 도구 버전·명령, PDF 전체 쪽수와 모든 PNG 경로·해시를 기록한다. manifest 생성은 시각 검수 완료가 아니다. 생성 담당은 최종 실행 후 모든 PNG를 개별 열람하고 페이지별 관찰을 별도 기록해야 한다. 2026-10-23 최종 실행과 16쪽 전수 검수 근거는 `.private/visual-review/producer-review.md`에 기록했다.
