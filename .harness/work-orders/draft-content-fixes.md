# 초안 내용 보완 결정

## 소유권과 적용 순서

`ProposalWriter`가 `docs/draft/proposal.md`, `docs/draft/ai-use.md`, 연구 기록의 내용 정합성을 수정한다. 문체 제안은 `.harness/reviews/s1.json`, `s2.json`의 내용 문제를 먼저 해결한 뒤 최종 ContestEditor가 직접 적용한다. 검수 중인 파일을 동시에 고치지 않으며 head의 실행 지시 후 시작한다. 공통 보안·개인정보·페르소나·외부값 파일화 규칙은 document-production.md를 따른다. 중간 빌드·테스트·렌더는 하지 않는다.

## head의 내용 결정

1. **담당자 하차 자동 감지 금지**: 실제 하차·탑승자 존재를 감지하는 기능은 없다. 담당자가 직접 ‘일시중지’를 선택한 뒤 하차하는 흐름과 Activity 중단·Service 연결 해제에 따른 일시중지를 구분한다. 모든 표·시나리오·설명에서 사람의 하차를 자동 인식하는 표현을 제거한다.
2. **무관한 문 개폐의 의미**: 앱은 개폐가 준비와 관련 있는지 자동 판별하지 않는다. 자동 강조 모드에서는 매핑된 지원 영역의 개방 이벤트를 표시한다. 무관한 개폐도 강조될 수 있고 이는 검증 대상이다. 사용자가 수동 그룹을 선택하면 해당 세션 동안 우선하며 이벤트는 문 상태만 갱신한다. ‘무관하면 자동으로 무시한다’고 읽히는 문장을 고친다.
3. **용어 첫 등장**: SDK·API는 본문 최초 등장 때 역할을 짧게 정의한다. 시나리오의 UX·비-DO는 앞에서 정의하거나 ‘플랫폼의 차량 화면 사용 제한’, ‘주행 중 사용 최적화를 선언하지 않은 화면’처럼 이미 이해 가능한 표현으로 바꾸고 기술 절의 정식 정의와 연결한다. 정의를 반복해 문장을 늘리지 않는다.
4. **사업 분모 통일**: N=100은 해당 월에 중복 제거한 ‘모집 후보 가구’로 고정한다. 아직 지원 환경·자연스러운 2인 동선을 통과한 가구가 아니다. e는 환경과 자연스러운 동선을 모두 통과한 가구 수/N인 ‘환경·동선 공동 통과율’로 정의한다. e=20/40/60%는 여전히 가정이다. 실제 관측 순서는 전체 노출→중복제거 후보 가구 N→지원환경 통과→자연스러운 동선 통과(이 수/N=e)→설치(i)→첫활성(a)→구매다. 하나의 필터를 두 번 곱하지 않는다. i의 분모는 환경·동선을 모두 통과한 가구이고 a의 분모는 그중 설치 가구다. U=N×e×i×a와 기존 계산값은 유지된다. 같은 가구 구성원·채널·다중설치는 한 번만 센다. 100가구와 손익용 2,000~4,000가구 및 채널당 200~400가구 모두 동일한 ‘지원환경·동선 검사 전 중복제거 후보 가구’ 단위로 통일한다. 적격이라는 표현을 서로 다른 단계에 중복 사용하지 않는다.
5. **비교 집계 단위**: 발견 조사로 확정한 같은 대표 과제의 조건별 짝지은 시간 차이를 먼저 계산한다. 한 조의 대표 과제가 여러 개이면 과제별 차이의 중앙값을 그 조의 차이로 삼고, 조별 차이들의 중앙값으로 3초/10초 기준을 판단한다. 맞지 않은 항목 선택·미준비 항목수도 조·과제 단위를 보존한다. 결측·실패를 0으로 채우거나 제외해 성공을 만들지 않으며 유효 짝 수와 사유를 함께 보고한다. 작은 표본 한계는 유지한다. 이 설계는 아직 실험하지 않았다.
6. **조건 순서**: 네 조건을 순환한 네 순서를 실험 전에 고정하고 10개 조를 3·3·2·2개 조로 배정한다. 어떤 조가 어느 순서에 배정되는지는 결과 확인 전에 무작위로 정한다. 각 조건의 대표 과제·정보량은 동일하며 불필요한 수동 전환을 강제하지 않는다. 연습은 분석에서 제외한다.
7. **모집·사례비 대응**: 발견 조사와 비교에 참여하는 10개 조·20명은 동일 집단이다. 1인 2만원·총40만원은 이 집단의 전체 참여 사례비 계획이며 추가 20명을 모집한다는 뜻이 아니다. 장기 재사용 검증의 최소20가구는 별도 후속 집단이고 이 40만원 예산으로 확보된 것으로 쓰지 않는다. 실제 모집·지출은 아직 없다.
8. **AI 고지**: 현재까지 조사·기획·집필·구간검토를 AI가 수행했다. 최종 편집 후에는 문체 편집까지 실제 활동에 포함한다. 사람의 실제 미수행 검토·SDK 실증·개발을 완료로 서술하지 않는다.

내용 수정 완료 후 변경 위치와 위 항목 대응을 보고한다. 최종 채점·전 페이지 시각 검수는 이후 별도 수행한다.
