# 출시 준비도 평가 기록

StayGo 1.2.0을 Pleos Connect 앱 마켓 출시 기준에 비추어 평가한 기록이다. 기준과 출처는 [`research/pleos-production-benchmark.md`](../../../research/pleos-production-benchmark.md)에 있다. 기준 R1~R10의 배점 합은 100점이며, 기준마다 필수 점검이 하나라도 실패하면 그 기준은 0점이다.

이 문서의 점수는 저장소 안의 독립 검토(코드, 보안·개인정보, 화면)로 매긴 내부 평가다. 현대자동차그룹이나 Pleos 앱 마켓의 심사 결과가 아니다.

## 평가 이력

| 회차 | 대상 | 점수 | 결과 |
|---|---|---|---|
| 1 | `cc51c9b` | 약 50 | R1(주행 안전), R3(실패 처리), R4(신호 신뢰), R8(화면 문구) 0점 |
| 2 | `3ee4104` | 약 75 | 코드 63/70, 보안·출시 위생 11/16, 화면 13/29. 좁은 창에서 요소가 잘려 창 대응 항목 0점 |

| 로그에 장소 이름이 남음 | 로그에서 장소 이름을 뺐다. |
| 좁은 창에서 화면이 잘리고 정보 버튼이 화면 밖으로 나감 | 상단 바와 판단 영역을 창 너비에 맞게 다시 짰다. 창 크기와 무관하게 같은 조작이 가능하다. |

### 2회차에서 나온 결함과 조치

| 결함 | 조치 |
|---|---|
| Go가 내비의 충전 경유지를 뺀 경로를 요청함 | 내비 경로에 충전 경유지가 있으면 Go가 그 경유지를 유지한다. 버튼에 경유지 이름을 적는다. |
| 동의를 철회해도 충전 기록과 세션이 남음 | 철회하면 충전 기록, 세션, 예비 SOC 설정을 지운다. |
| 배터리 전력량을 읽지 못하는 차에서 화면 복귀 뒤 충전 확인이 동작하지 않음 | 연결 대기 시간이 지나면 경과 시간만으로 세션을 정리하고 충전 상태나 운전자 확인으로 이어 간다. |
| 주행 제한 리스너 등록 전에 현재 값을 먼저 반영함 | 리스너를 먼저 등록한다. 등록이 실패하면 잠금 상태로 남는다. 응답이 없으면 10초마다 다시 연결한다. |
| 동의·기록 삭제가 잠금 중에도 엔진에서 실행됨 | 잠금 중에는 무시한다. |
| 차량·내비 연결 실패 뒤 다시 시도하지 않음 | 화면이 보이는 동안 10초마다 다시 연결한다. |
| 보고 단위가 거친 차에서 저전력 충전을 종료로 봄 | 같은 값이 이어지다 다시 오르면 그 간격을 보고 주기로 기억하고, 그 세 배(최대 45초)까지 기다린다. |
| Go 직후 경로가 취소되면 이전 목적지와 도착 SOC가 남음 | 대기 시간이 끝나면 목적지를 지운다. |
| 차량 속성 콜백의 예외가 앱을 종료시킬 수 있음 | 콜백 안에서 예외를 버린다. |
| 같은 화면의 도착 SOC와 부족분이 맞지 않음(7%와 7.1%p), 소수점 표기 | 부족분은 표시된 도착 SOC에서 계산한 정수로, 대기 시간은 올림한 정수 분으로 적는다. |
| 좁은 창에서 스테퍼·추세 화살표·거리가 잘리고 알림이 상단 바를 가림 | 가장 낮은 창에서는 이유 줄을 빼고, 화살표는 타일 이름 옆에 두고, 좁은 창의 목적지 칩은 이름만 보인다. 좁은 창의 알림은 판단 영역의 칩 자리에 보인다. |
| 연결되지 않았을 때도 「목적지 없음」으로 표시 | 차량·내비를 읽지 못할 때는 「목적지 미확인」으로 적는다. |
| Stay 알약은 회색인데 Stay 버튼은 강조됨 | 버튼이 강조되면 알약도 채운다. |
| Stay 판단에 언제까지인지가 없음 | 「N kW 아래로 줄면 출발 안내」를 이유 줄에 적는다. |
| 차단된 화면에서 버튼을 눌러도 반응이 없음 | 사유를 알림으로 보인다. |
| 주행 상태 확인이 끝나지 않을 때 안내가 없음 | 5초 뒤 「확인할 수 없어 화면을 잠갔습니다」와 자동 해제 안내로 바꾼다. |
| 시스템 언어가 한국어가 아니면 단어 중간에서 줄이 바뀜 | 글자 로캘을 한국어로 고정했다. |
| 안내문에 주행 제한 조회와 주소·장소 식별자가 빠짐, 동의에 버전이 없음 | 안내문에 추가하고, 안내문이 바뀌면 다시 동의를 받는다. |
| 로그 점검이 앱 태그만 봄 | 프로세스 전체 로그에서 장소 이름을 찾는다. |
| 기기 간 이전 제외 규칙 없음, 서명 정보가 없으면 서명 없는 release가 만들어짐 | `dataExtractionRules`를 추가하고, 서명 정보가 없으면 release 빌드를 실패시킨다. |

프레임 통계는 참고값이다. 에뮬레이터가 소프트웨어 렌더링(swiftshader)으로 돌아 지연 프레임 비율(69%)이 실차 성능을 나타내지 않는다.

## 확인하지 못한 항목

- 실차 신호: 충전 상태(`EV_CHARGE_STATE`)와 순간 충전전력은 에뮬레이터에서 고정값이라, 이 신호를 쓰는 경로는 JVM 테스트와 시뮬레이터로만 확인했다. 실차에서 배터리 전력량의 갱신 주기와 해상도가 다르면 충전 인식 시간이 달라진다.
- 주행 제한: 에뮬레이터의 기어·속도 입력으로만 확인했다. 실차의 제한 전환 시점은 확인하지 못했다.
- 앱 마켓 심사: Pleos 권한의 승인, 등록 정보, 심사 체크리스트 통과 여부는 심사를 받아야 알 수 있다.
- 화면: Pleos 창 규격 네 가지와 주야 모드, 글꼴 130%는 일반 Android 에뮬레이터의 디버그 빌드로 확인했다. Pleos 에뮬레이터에서는 기본 창 크기만 확인했다. 로터리 조작은 지원하지 않는다고 선언했다.
- Go 뒤의 내비 동작: 내비 경로에 충전 경유지가 있으면 Go는 그 경유지를 유지한 경로를 요청한다. 경유지 없는 경로를 요청했을 때 내비가 경유지를 다시 넣는지는 확인하지 못했다.
- 시연 시점: 같은 충전 곡선에서 Go가 나오는 시점이 실행마다 충전 시작 뒤 181초에서 239초 사이로 달랐다. 내비가 계산하는 경로 소비 전력량이 실행 시각에 따라 달라지기 때문이다.
- 음성: 음성 안내와 음성 명령은 없다.

## 남은 과제

- 경유지 최대 출력의 기기 내 목록(`assets/stations.tsv`): 한국환경공단 충전소 정보 OpenAPI의 활용신청이 승인되어야 만들 수 있다. 목록이 없으면 내비가 최대 출력을 주는 경유지만 비교한다.
- 앱 업데이트 안내: 최신 버전을 알려 줄 출처가 없어 구현하지 않았다. 마켓 등록 뒤에 정한다.
- 목표 SOC까지 남은 시간과 주행 가능 거리(km): 양산 EV 화면에 있는 표시이며 이 앱에는 없다.
- 코드 축소(R8): 적용하지 않았다.
