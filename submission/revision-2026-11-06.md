## 개정 요지

기존 원고는 「한쪽 문에서 준비하다가 반대쪽으로 가면 앞좌석 확인 담당자가 헷갈린다」는 한 줄 설명에 그쳐, 문제가 가벼운 협업 실수로 읽힐 여지가 있었다. 또한 외출마다 문별 항목을 손으로 배분하는 절차가 부담으로 남았다.

이번 개정은 같은 제품 목적(문 개방 맥락과 미확인 항목의 연결)을 유지하면서, (1) 실제로 준비가 중단되고 누락·왕복이 발생하는 장면을 구체화하고, (2) 외출 유형 템플릿·직전 목록 재사용·원탭 시작으로 설정 단계를 줄인다. 수요 빈도와 시장 규모는 기존과 같이 발견 조사로 확인하며, 문헌 수치로 추정하지 않는다.

## 개정문 — 2. 기획 배경

### 한 사람이 안에 남아 확인하는 동반 외출

[가정·설계] 초기 고객은 반려견과 함께 외출한 두 사람 가운데 한 명이 앞좌석에 남아 확인을 맡고, 다른 한 명이 후석 양쪽 문에서 이동장·가방·의료용품을 챙기는 사용자다. 앞좌석에서는 후석 문 안쪽과 바닥이 잘 보이지 않으며, 동승자가 한쪽 문에서 다른 쪽으로 옮기면 확인 담당자는 말로만 상태를 확인해야 한다. 본 앱은 이 중단·복귀 순간에 관측된 문 개방과 그 문에 남은 미확인 항목을 한 화면에 연결한다. 실제 준비 여부는 두 사람이 말로 확인하고, 앞좌석 사용자가 직접 기록한다.

문제가 「어느 문에서 무엇을 했는지 잠깐 헷갈리는」 수준에 그치지 않는 이유는, 후석 준비가 한 번에 완료되지 않고 문 사이 왕복과 시간 압박이 겹치기 때문이다. 아래 장면은 초기 가설을 설명하기 위한 [가정·설계] 예시이며, 발생 빈도는 발견 조사로 확인한다.

- **동물병원 방문, 긴장한 중·대형견.** 주차 후 한쪽 문에는 이동장과 기저귀·물티슈가, 반대쪽에는 진료비·진료기록·목줄·배변봉투가 나뉜다. 반려견이 보채면 동승자는 이동장 쪽을 먼저 열고 달랜 뒤, 접수에 필요한 가방을 챙기러 반대쪽으로 이동한다. 앞좌석 담당자는 병원 입구와 시계를 보며 「이동장 잠금은 됐고, 목줄은? 진료기록은?」을 되묻게 된다. <!-- style-exempt --> 문이 바뀌는 순간마다 미확인 항목이 섞이면, 말로만 확인하는 부담이 증가한다.
- **비 오는 날, 한쪽만 열 수 있는 주차.** 옆 차량이나 벽 때문에 후석 한쪽 문만 열린다. 동승자는 열린 쪽에서 이동장 주변 용품을 챙긴 다음, 차를 조금 빼거나 돌아가 반대쪽 문을 연다. 비에 젖지 않으려 서두르는 동안 앞좌석에서는 닫힌 쪽의 남은 항목이 보이지 않는다. 문이 바뀌는 맥락을 화면에 남겨 두지 않으면, 확인 담당자는 방금 완료한 쪽과 아직인 쪽을 다시 물어야 한다.
- **아이와 반려견을 함께 태운 외출.** 앞좌석 한 사람은 아이의 하차·안전벨트를 살피며 자리를 비우기 어렵고, 다른 한 사람이 후석 양쪽을 오가며 유모차 가방과 반려견 용품을 배분한다. 동시에 두 문이 잠깐 열리거나, 한쪽을 열어 둔 채 반대쪽으로 옮기는 일이 이어지면, 앞좌석에서는 「지금 어느 문 기준으로 확인해야 하는지」가 중단된다.
- **무거운 짐과 반대쪽 소형 물품.** 한쪽에는 이동장과 담요처럼 무게가 있는 준비가, 다른 쪽에는 간식·약·여분의 목줄처럼 빠지기 쉬운 소형 물품이 있다. 무거운 쪽을 먼저 내린 뒤 소형 물품을 잊고 문을 닫으면, 병원·산책 입구에서 다시 차로 돌아오는 왕복이 발생한다. 앱은 문을 닫았다고 항목을 완료하지 않으며, 앞좌석 확인이 완료되기 전까지 미확인으로 남긴다.

이 기획에서 차량 화면을 쓰는 이유는 모든 탑승자가 큰 화면을 보기 때문이 아니다. 확인 담당자가 이미 앞좌석에 남는 흐름에서, 관측된 문 변화와 중단한 준비 항목을 한곳에 두기 위해서다. 혼자 모든 준비를 하는 사용자와 두 사람 모두 곧바로 차 밖으로 나가는 사용자는 초기 대상에서 제외한다. 실제 환경에서 후석 두 영역의 문 상태 조회와 알림 수신이 지원되어야 하며, 운전석 문만 읽을 수 있는 환경은 같은 지원 대상으로 포함하지 않는다.

### 설정 부담을 줄이는 시작 방식

[가정·설계] 문별 항목을 매번 처음부터 입력하게 하면, 설치·협업 부담이 재탐색 이득을 상쇄할 수 있다. 따라서 초기 제품은 설정 단계를 아래처럼 짧게 둔다.

| 시작 방식 | 사용자 조작 | 앱의 처리 |
|---|---|---|
| 외출 유형 템플릿 | 병원·산책·여행 중 하나를 고른다. | 문별로 나뉜 기본 목록(각 최대 3개, 총 최대 6개)을 채운다. 사용자는 빠진 항목만 수정하거나 삭제한다. |
| 직전 목록 재사용 | 「지난번 그대로」를 고른다. | 직전에 확인을 마친 문별 배치를 불러온다. |
| 원탭 시작 | 템플릿 또는 직전 목록을 고른 뒤 시작을 누른다. | 플랫폼의 차량 화면 사용 제한을 확인한 다음, 문별 미확인 항목 화면으로 바로 들어간다. |
| 수동 조정(선택) | 주차 중 항목·문 배치만 수정한다. | 문별 설정 자체를 차별 기능으로 주장하지 않는다. |

<p>표 A. 계획한 사전 설정 완화.</p>

반려견 이동용품은 첫 템플릿으로 제안한다. 병원 템플릿에는 이동장·목줄·진료기록·배변봉투처럼 빠지기 쉬운 항목을, 산책 템플릿에는 물·간식·배변봉투를, 여행 템플릿에는 이동장·담요·여분 목줄을 기본값으로 둔다. 사용자가 정하는 준비물을 각 문에 두되, 앱이 이동장 개방이나 동물 하차를 지시하지 않는다. **물건·동물의 존재 감지, 방치 예방, 법적 준수 확인 또는 하차 안전 허가는 제공 범위가 아니다.**

### 생활 집단의 근거와 확인할 수요

[문헌] 농림축산식품부가 2026년 2월 12일 발표한 「2025년 반려동물 양육현황조사」는 3,000가구 방문 면접조사이며, 반려동물 양육가구 비율은 29.2%, 양육가구 중 개 양육 비율은 80.5%다.[14] 같은 발표의 「2025년 동물복지에 대한 국민의식조사」는 5,000명 온라인 조사이며, 반려견 외출 시 목줄·인식표·배설물 수거 등 준수사항을 잘 지킨다는 긍정 응답은 48.8%다.[14]

이 자료는 반려동물 외출 준비를 검토할 생활 집단과 정책적 관련성을 보여준다. 두 조사는 모집단과 조사 방법이 다르므로 비율을 곱해 시장 규모를 계산하지 않는다. 29.2%를 차량 동반 이동자나 Pleos 앱 고객 비율로 사용하지 않으며, 48.8%의 나머지를 실제 미준수율로 해석하지 않는다. 본 앱이 대상으로 하는 자연스러운 2인 분담 동선의 빈도와 중단 후 재탐색 부담은 발견 조사로 확인한다.

## 개정문 — 4. 주요 사용 시나리오

### 두 문 사이에서 중단된 준비를 이어가는 장면

[가정·설계] 두 보호자가 중형견과 동물병원 예약을 위해 주차하였다. 비는 오지 않으나 옆 차량 때문에 조수석 쪽 후석 문만 먼저 열린다. 한 명은 앞좌석에서 아이 좌석과 준비 확인을 맡고, 동승자는 열린 쪽에서 이동장·기저귀를 확인한 뒤 접수 가방을 챙기러 반대쪽 문으로 돌아간다. 앱은 사용자가 직접 연다. 내비게이션 도착이나 문 열림으로 자동 실행하지 않는다.

| 단계 | 사람의 행동 | 앱의 응답 |
|---|---|---|
| 사전 설정 | 주차 후 「병원」 템플릿을 고르거나 「지난번 그대로」로 시작한다. 필요하면 항목만 수정한다. | 읽기 가능한 두 후석 영역에 총 최대 6항목을 연결한다. 매번 빈 목록부터 채우지 않는다. |
| 시작 | 앞좌석 담당자가 원탭으로 앱을 연다. | 플랫폼의 차량 화면 사용 제한을 확인한 뒤 문별 미확인 항목을 표시한다. |
| 첫 문 작업 | 동승자가 열린 후석 문에서 이동장 쪽을 준비한다. | 관측된 문 그룹을 강조한다. 담당자는 말로 확인한 항목만 완료한다. |
| 중단·이동 | 접수 가방이 반대쪽에 있어 동승자가 돌아 반대쪽 문을 연다. 앞좌석에서는 후석 바닥이 보이지 않는다. | 새 그룹을 강조하고 첫 그룹의 「남은 준비」를 유지한다. 닫힌 문을 완료로 바꾸지 않는다. |
| 복귀 | 반려견이 보채 동승자가 첫 문으로 돌아온다. | 문이 다시 열리면 미확인 항목을 강조한다. 계속 열려 있었다면 자동 이동 추정 없이 수동 선택을 제공한다. |
| 종료 | 동승자가 실제 준비 완료를 알린다. 잊은 목줄·진료기록이 있으면 미확인으로 남아 왕복을 줄인다. | 담당자가 항목 상태를 확인하고 세션을 직접 종료한다. |

<p>표 B. 화면 접근이 유지되는 2인 동반 외출 시나리오(개정).</p>

미확인 항목은 문을 닫아도 미확인 상태로 남는다. 자동 강조 모드에서는 매핑된 지원 영역의 개방 이벤트를 반영하므로 준비와 무관한 개폐도 강조될 수 있다. 앱이 관련성을 판별하지는 않으며, 원치 않은 강조 횟수를 사용자 가치 검증에서 측정한다. 수동 그룹을 선택한 상태에서는 모든 문 이벤트가 문 상태만 갱신하고 선택한 그룹을 바꾸지 않는다.

앞좌석 담당자는 하차 전에 직접 「일시중지」를 선택한다. 앱은 사람의 실제 하차·탑승자 존재를 감지하지 않는다. Activity가 중단되거나 차량 Service 연결이 해제되면 진행을 일시 중지한다. 재개 때 현재 상태를 다시 조회하며, 문 열림이나 지난 완료 기록만으로 준비가 완료되었다고 안내하지 않는다.

플랫폼의 차량 화면 사용 제한이 변경되면 준비 확인보다 제한을 우선한다. 화면을 사용할 수 없는 상태에서는 주행 중 사용 최적화를 선언하지 않은 화면을 닫거나 이탈시킨다. 사용자는 주변 교통과 실제 준비 상황을 별도로 판단한다.

## 원문에 넣을 시나리오 핵심 문단(확정 후보)

아래 문단은 제출 원고 4항 도입부에 그대로 넣을 수 있는 개정 문장이다.

> [가정·설계] 두 보호자가 중형견과 동물병원 예약을 위해 주차하였다. 옆 차량 때문에 후석 한쪽 문만 먼저 열리며, 한 명은 앞좌석에서 아이와 준비 확인을 맡고 동승자는 열린 쪽에서 이동장·기저귀를 확인한 뒤 접수 가방을 챙기러 반대쪽 문으로 돌아간다. 앞좌석에서는 후석 문 안쪽과 바닥이 잘 보이지 않으므로, 문이 바뀌는 동안 「이동장은 됐고 목줄·진료기록은 아직인지」를 말로만 확인하면 누락과 차 안 왕복이 발생하기 쉽다. 앱은 사용자가 병원 템플릿 또는 직전 목록으로 원탭 시작하며, 내비게이션 도착이나 문 열림으로 자동 실행하지 않는다. 관측된 문 개방에 맞춰 미확인 항목을 강조하되, 문을 닫았다고 완료로 바꾸지 않는다. 물건·동물의 존재 감지, 방치 예방, 법적 준수 확인 또는 하차 안전 허가는 제공 범위가 아니다.
